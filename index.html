4-MONTH MACHINE LEARNING INTERNSHIP July 2026 – October 2026

FlyRank AI — Industrial Search Ranking & Query Triage

Machine Learning Engineer Intern • Remote / San Francisco, CA

🎯 Production Problem & Core Mandate

Enterprise search optimization systems handle tens of millions of query logs daily. Traditional Pandas/memory-based ML pipelines frequently crash with Out-Of-Memory (OOM) exceptions when aggregating search logs. Furthermore, standard random train/test data splitting suffers from severe data leakage because popular search queries appear repeatedly, causing models to achieve artificial 99% test accuracy that collapses when faced with unseen user queries in production.

⚡ 3 Core Engineering Solutions

1. Out-of-Core DuckDB Streaming (78.8 Million Rows)
Designed a streaming parquet cursor architecture in DuckDB that processes 78,829,314 rows in chunked blocks. Kept peak resident memory consumption capped strictly under 1.3 GB RAM, enabling massive query triage on standard commodity machines without multi-thousand dollar RAM clusters.
2. Leak-Free Domain-Stratified GroupKFold Cross-Validation
Grouped dataset by query clusters and top-level domains. Ensured test folds never contain queries present in training folds. This verified that the model achieved a genuine 0.932 AUC on novel, unseen search intents rather than cheating by memorizing repetitive keywords.
3. Probability Calibration & Brier Loss Minimization (0.043)
Applied isotonic regression calibration over LightGBM outputs, minimizing Brier calibration score to 0.043. This guarantees that when the system predicts an 80% likelihood of zero-click CTR anomaly, true real-world user click behavior reflects that probability with high fidelity.
